# PRD-F — Integration, Decision Memo & CI

**Owner paths:** `Makefile`, `README.md`, `pyproject.toml`, `.github/`, `src/retrylab/reporting/`, `docs/memo.md`, `tests/integration/`
**Consumes:** everything · **Produces:** the one-command pipeline, CI, the decision memo, the portfolio README
**Runs in two phases.** Phase 1 runs in parallel with A–E. Phase 2 runs after A–E are merged.

## 1. Goal
Make the project run with one command, prove it end to end, and package it for a recruiter: a README that sells it in 30 seconds and a decision memo that shows data storytelling.

## Phase 1 — in parallel with A–E

### 1.1 Makefile
```
setup      pip install -e ".[dev]"
simulate   python -m retrylab.sim --config config/sim.yaml --out data/raw
dbt        dbt build --project-dir dbt --profiles-dir dbt
design     python -m retrylab.design --out reports/power_analysis.json
analyze    python -m retrylab.analysis --db data/warehouse.duckdb --out reports/
memo       python -m retrylab.reporting --results reports/results.json --power reports/power_analysis.json --out docs/memo.md
export     python -m app.export --out exports/powerbi/
all        simulate dbt design analyze memo export
app        streamlit run app/Home.py
test       pytest
lint       ruff check . && ruff format --check .
clean      remove data/, reports/*.json, reports/figures/, exports/, docs/memo.md
```
Export `PROJECT_ROOT := $(CURDIR)` for every target.

### 1.2 Memo renderer — `src/retrylab/reporting/`
- A Jinja2 template `memo.md.j2` rendered from `results.json` + `power_analysis.json` only. **No hard-coded numbers in the template.**
- Memo structure (one page, Amazon-style narrative, about 500 words):
  1. **TL;DR:** decision + headline lift + annualized impact, in 2 sentences.
  2. **What we tested and why.**
  3. **Results:** primary metric with CI, the CUPED-adjusted figure, and an SRM check note.
  4. **Where it works:** significant segments in plain English ("Customers declined for insufficient funds recovered 6.1pp more often…").
  5. **Guardrails:** what we protected and whether it held.
  6. **Recommendation & next steps:** scope, rollout plan (e.g., 10% → 50% → 100%), and what to test next.
  7. **Caveats:** simulated data, the assumptions behind the revenue estimate.
  8. Embedded figures from `reports/figures/`.
- Number formatting helpers: percentage points as `3.2pp`, rates as `34.5%`, money as `$1.2M` / `$48,300`, CIs as `[2.4pp, 4.0pp]`.
- Develop against a hand-written fixture `tests/integration/fixtures/results_*.json` covering all three decision branches. The template must read naturally for each one (a test renders all three).

### 1.3 CI — `.github/workflows/ci.yml`
On push/PR: set up Python 3.11 → `make setup` → `make lint` → `make test`. A second job runs `make all` with `n_customers: 5000` (via an override config, `config/sim.ci.yaml`, created in phase 2 by asking A in a handoff, or by F in phase 2 if A didn't) and uploads `reports/` and `docs/memo.md` as artifacts.

### 1.4 README skeleton
Placeholders are filled in phase 2.

## Phase 2 — after A–E are merged

### 2.1 Integration
- Run `make clean all`. Fix integration bugs **only inside your owned paths**. For bugs in other workstreams, write them up in `HANDOFF-F.md` with the exact repro steps.
- `tests/integration/test_end_to_end.py` (marked `@pytest.mark.slow`): runs the full pipeline at 5k customers, then asserts:
  - `results.json` validates against D's schema
  - the SRM check passes
  - the overall lift CI contains the blended true effect from `config/ground_truth.yaml` (allowed here only, per C7)
  - the `insufficient_funds` segment is BH-significant and positive
  - the `expired_card` segment is not significant
  - `memo.md` exists and contains no `{{` or `None`
- A reproducibility test: two runs produce identical `results.json` (with `--frozen-time`).

### 2.2 README (portfolio-facing)
1. A one-line hook plus the headline result.
2. A screenshot of the dashboard overview and the segment forest plot.
3. "The question," "What I built" (an architecture diagram in Mermaid: sim → dbt → analysis → dashboard/memo), and "Key results" (numbers pulled from `results.json` by a small script, not typed in by hand).
4. **Skills shown**, mapped to the Stripe posting (the table from 00_OVERVIEW §1).
5. Quickstart (`make setup all app`).
6. Repo tour, then honest limitations (simulated data, effect sizes are planted).
7. **Resume bullets**, generated by `python -m retrylab.reporting.bullets` from `results.json` and printed in the README. Three bullets, each under 160 characters, with real numbers.
